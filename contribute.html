Add something to the index

If you have built an activity, translated one, or found a good one that is not listed, we want it here. You do not have to host it with us and you do not have to hand it over — the index points at wherever it already lives.

The two-minute way

Fill in the form

A short GitHub issue form asks for the same handful of fields you see on every resource page. A maintainer turns it into a record. You need a GitHub account but nothing else. If you would rather not, email {{ site.contact_email }} and we will do the typing.

The direct way

Add one file to _resources/ and open a pull request. The file is YAML front matter followed by a few paragraphs of description. Automated checks will tell you if a field is missing or a term is not in the vocabulary, so you do not need to memorise the schema. Copy an existing record and edit it.

What we will and will not list

  • It has to be openly available, with no login and no fee.
  • It has to use CMS open data, or teach something you need in order to use it.
  • It does not have to be finished, polished, or maintained. Unmaintained material is labelled as such and stays listed, because a rough activity someone can find beats a perfect one they cannot.
  • We will not rewrite documentation that already exists elsewhere. If the Portal or the Guide covers it, we link to it.

Tell us how it went

The most useful thing you can add is not a new activity but a paragraph about running an existing one: what you cut, what confused students, how long it really took. Share that here.
